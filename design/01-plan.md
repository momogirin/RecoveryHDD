# 01. 계획서

## 1. 목표
APFS 메타데이터가 사라진 외장하드에서 **사진(JPEG/RAW)·영상(MP4/MOV)을 안전하게 꺼내는**
무료 오픈소스 도구. 비전문가가 `검사 → 계획 → 복구 → 검증`을 화면에서 따라 할 수 있게 한다.

### 사용자가 요구한 흐름
1. **검사 버튼**: 누르면 디스크를 읽기 전용으로 검사해 종류별 개수·용량을 보여 준다.
2. **복구 계획**: 검사 결과를 보고 종류, 개수, GB 단위 묶음을 정한다.
3. **폴더 지정**: 저장 위치를 고르면 여유 공간을 확인한다. 모자라면 막는다.
4. **실행·이어하기·검증**: 묶음 단위로 꺼내고, 끊겨도 이어서 하고, 마지막에 열리는지 확인한다.

### 비목표 (지금은 하지 않는다)
- 원본 디스크 수리/복원(쓰기 동작 일체)
- 원래 파일명·폴더 구조 복원 (옛 메타데이터가 없는 경우. 있는 경우는 7단계에서 별도 검토)
- 암호화된 볼륨의 복호화
- 클라우드 업로드, 계정, 원격 접속

## 2. 절대 원칙 (코드와 UI 양쪽에서 강제)
| # | 원칙 | 강제 방법 |
|---|---|---|
| 1 | 원본 디스크에 쓰지 않는다 | 장치는 `O_RDONLY`로만 연다. 쓰기 함수 자체가 없다. 테스트가 소스 전체를 grep해 쓰기 플래그를 검사한다 |
| 2 | 결과는 원본 디스크와 저장소 밖에만 쓴다 | 저장 폴더 검증 함수가 (a) 원본 장치의 마운트 경로 (b) 저장소 폴더 (c) 시스템 폴더를 거부한다 |
| 3 | 저장 전 용량 확인 | 묶음 시작 전 `필요량 + 여유 마진`을 확인한다. 부족하면 시작하지 않는다 |
| 4 | 모르는 것은 추측하지 않는다 | 판정은 `확인됨 / 의심 / 불명`으로 표시한다. 모르면 "불명"이라고 쓴다 |
| 5 | 관리자 권한은 최소로 | 서버는 `127.0.0.1`에만 바인딩하고 실행마다 새 토큰을 요구한다. 임의 경로의 장치를 받지 않고 목록에서 고른 것만 쓴다 |
| 6 | 복구 결과는 열어서 확인한다 | 마지막 단계에서 모든 파일을 검증하고 실패 목록을 보여 준다 |

## 3. 구조
```
브라우저 (HTML/JS 시안 → 나중에 React)
      │ HTTP, 127.0.0.1 + 토큰
┌─────▼──────────────────────────────┐
│ server  (관리자 권한으로 실행)        │
│  · 장치 목록 · 작업 관리 · 진행률      │
│  · 세션 폴더에 상태 저장(이어하기)     │
└─────┬──────────────────────────────┘
┌─────▼──────────────────────────────┐
│ engine  (apfsrecover)               │
│  blockdev  읽기 전용 장치 (OS별 구현)  │
│  inspect · scan · survey            │  ← 구현됨
│  catalog   서명 탐색 + 길이 계산      │  ← 다음 단계
│  carve     계획에 따라 파일 추출      │  ← 샘플 구현됨
│  verify    열림 검증                  │
└────────────────────────────────────┘
```
- 엔진은 서버 없이 **명령줄로도 단독 실행**된다. UI는 엔진의 얇은 껍데기다.
- 세션 폴더(기본 `~/Documents/recovered/session`, 저장 폴더와 별개)에 `catalog.jsonl`, `plan.json`, `progress.json`을 둔다.
  전부 사람이 읽는 텍스트라서 중간에 끊겨도 이어서 할 수 있고 눈으로 확인할 수 있다.

## 4. 단계별 계획
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P0 | 진단 (완료) | 컨테이너 상태, 옛 메타데이터 부재, 데이터 분포 확인. 샘플 8개 추출·검증 |
| P1 (완료) | **catalog**: 디스크를 한 번 읽어 JPEG/RAW/MP4/MOV 위치·길이·촬영일·구조 점검 결과를 목록으로 저장 | 560GB를 오류 없이 처리하고 중단/재개 가능. 합성 데이터 단위 테스트 통과 |
| P2 (완료) | 서버 + API (`03-engine-api.md`) | 장치 목록, 검사 시작/취소, 진행률, 결과 조회 |
| P3 (완료) | UI: 디스크 선택 → 검사 → 결과 | 시안과 같은 흐름이 실제로 동작 |
| P4 (완료) | UI: 복구 계획 → 실행 → 이어하기 | 묶음 단위 추출, 용량 가드, 날짜별 폴더 |
| P5 (완료) | 검증 단계 | JPEG 전체 디코드, RAW/영상 헤더·구조 확인, 실패 목록 |
| P6 (코드 완료, **실제 디스크 실측 전**) | Windows 지원 | `\\.\PhysicalDriveN` 읽기, GPT 오프셋, 정렬 읽기. 가짜 이미지·가짜 PowerShell 출력으로 테스트 82개 통과. `RecoveryTool.exe` 빌드·창·화면 확인. 실제 외장 디스크 읽기, UAC 창, 케이블 분리는 미확인 (`04-distribution.md`) |
| P7 | 공개 준비 | README, 라이선스, 테스트, 보고서 개인정보 제거 |

각 단계는 작게 끊어 결과를 보여 주고 확인받은 뒤 다음으로 간다. 커밋은 요청이 있을 때만 한다.

## 5. 핵심 설계 결정
- **catalog를 따로 둔다.** 디스크 전체 읽기(약 1시간/560GB)는 한 번만 하고, 복구 계획은 목록을 바탕으로 몇 번이든 바꿀 수 있다.
- **디스크 순서대로 추출한다.** HDD는 순차 읽기가 빠르므로, 묶음 안에서는 오프셋 순으로 읽는다.
- **파일명:** `날짜/종류_일련번호_오프셋.확장자` (예: `2024-03-06/jpg_000123_blk25792.jpg`). 촬영일이 없으면 `날짜불명/`.
  - 2026-11-25 변경: 촬영 시각이 있으면 `20240306_143012_CanonEOSR8_000123.jpg`. 이전 기록을 이어할 때는 이전 이름을 유지한다(`07-roadmap.md` D).
- **중복·삭제 파일:** 시그니처 복구는 지워진 옛 파일도 찾는다. 목록에 그대로 표시하되 구분할 방법이 없으므로 "삭제 여부 불명"이라고만 쓴다.
- **끊김 대응:** 장치가 사라지면(`ENXIO`) 즉시 멈추고 이어서 할 위치를 기록한다. 재연결 후 장치 번호가 바뀌어도 UI에서 다시 고른다.

## 6. 위험과 대응
| 위험 | 영향 | 대응 |
|---|---|---|
| 큰 영상이 조각나 있음 | 일부 영상이 깨지거나 잘림 | 구조 점검에서 `의심` 표시, 검증 단계에서 실패 목록. 영상은 "복구 보장 없음"이라고 UI에 명시 |
| 초기화로 일부 영역이 덮어쓰임 | 일부 파일 손실 | 손실량은 catalog 결과로 숫자로 보여 준다 |
| 케이블 분리 | 작업 중단 | 즉시 멈추고 재개 위치 저장 |
| `crx `의 CR3/CRM 구분 미검증 | 영상 RAW(CRM)를 사진으로 오표시 | 알려진 한계로 기록. CNCV/박스 검사로 구분하는 작업을 P1에 포함하되, 검증 전에는 "미확인" 표시 |
| 윈도우 raw 읽기 제약 | P6 지연 | 맥에서 먼저 완성하고 윈도우는 실측 후 고친다 |
| 서버가 관리자 권한 | 로컬 악용 위험 | 127.0.0.1 한정, 토큰, 장치 목록에서 선택, 쓰기 기능 없음 |
| 보고서 개인정보 | 공개 시 노출 | 보고서는 UUID 등을 가려서 저장하고 P7에서 재점검 |

## 7. 결정 사항 (2026-11-23 확정)
1. **폴더 구조:** 종류별을 위에, 그 아래 날짜별. 예: `사진/2024-03-06/…`, `RAW/…`, `영상/…`
   - 이유: 영상 날짜가 하루 어긋날 수 있고(UTC), CR3/CRM 구분이 미검증이라 종류를 먼저 나눠 영향을 가둔다.
   - **구현됨** (`extract.py` `dest_relpath`). 폴더 이름은 `사진/RAW/영상/기타`. 5절의 `날짜/종류_…` 예시는 `사진/날짜/종류_…` 로 읽는다.
2. **`의심` 영상:** 기본으로 꺼내되 `영상/_의심/`에 따로 둔다. 설정에서 끌 수 있고 기본값은 켜 둔다. UI에 "복구 보장 없음"을 표시한다.
3. **회사 PC:** 전제로 하지 않는다. 개인 윈도우 PC에서 P6를 먼저 구현·실측한다. 회사 PC는 나중에 파이썬/관리자 권한만 확인하고, 막히면 PyInstaller `.exe` 단독 배포를 검토한다.
4. **중복 파일:** 내용이 같은 것(길이+일부 해시)은 하나만 꺼내고 나머지는 목록에만 남긴다. UI에 "중복 N개 건너뜀"을 표시한다. 삭제 여부는 계속 "불명"으로 쓴다. 
   - **구현됨**, 단 방식을 바꿨다: 목록 단계가 아니라 **꺼내는 중에** 전체 내용의 SHA-256 으로 비교한다(길이+일부 해시보다 정확하고 추가 읽기가 없다). 같은 내용은 `duplicates.jsonl` 에 기록하고 파일은 남기지 않는다. 단점: 중복도 한 번은 읽는다.
5. **라이선스:** MIT. P7에서 적용한다.
