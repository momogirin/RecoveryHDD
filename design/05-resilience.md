# 05. 돌발상황 대응

원칙: **원본 디스크는 읽기만 하므로 어떤 돌발상황에도 원본은 바뀌지 않는다.** 대응의 목적은 (1) 이미 한 작업을 잃지 않고, (2) 잘못된 데이터를 꺼내지 않고, (3) 이어서 할 수 있게 하는 것이다.

검증 열의 의미: **테스트** = 자동 테스트(`tests/`), **브라우저** = 헤드리스 Chrome으로 화면을 직접 조작해 확인, **시뮬레이션** = 실제 사고가 아니라 오류를 흉내 내어 확인, **미확인** = 실제 상황으로 확인하지 못함.

| 상황 | 처리 | 검증 |
|---|---|---|
| 케이블이 빠짐/장치가 사라짐 | 즉시 멈추고 이어서 할 위치를 저장. 안전하다는 안내 | 테스트, 시뮬레이션(실제 케이블 분리는 미확인) |
| 다시 꽂음(장치 번호가 바뀜) | 디스크 앞부분 지문으로 같은 디스크임을 알아보고 **[이어서 하기]** 표시 | 브라우저(시뮬레이션) |
| **다른 디스크를 꽂음** | 검사했던 디스크와 지문이 다르면 복구·이어하기 거부 | 테스트 |
| 불량 섹터로 한 파일만 못 읽음 | 3번 다시 시도 후 그 파일만 건너뛰고 기록(`failed.jsonl`), 나머지는 계속. 같은 파일이 묶음을 막지 않음 | 테스트 |
| 연속 5개를 못 읽음 | 디스크가 불안정하다고 보고 중단 | 테스트 |
| 저장 장치 쪽 오류(저장 드라이브가 빠짐 등) | 원본 문제와 구분해서 "저장 폴더에 쓰지 못했습니다"로 안내 | 테스트 |
| 저장 공간 부족 | 시작 전 점검 + 파일마다 확인. 자동 모드는 복구 시작 전에 멈추고 계획 화면으로 | 테스트, 브라우저 |
| 도구가 갑자기 꺼짐/컴퓨터가 꺼짐 | 다음 실행에서 "중간에 멈춘 기록"을 안내하고 이어서 하기. `run_state.json` | 테스트, 브라우저(상태 파일을 만들어 확인) |
| 꺼질 때 목록 파일의 마지막 줄이 잘림 | 깨진 줄은 건너뜀. 검사 목록은 진행 위치 이후 항목을 버리고 이어서 다시 읽음(중복 방지) | 테스트 |
| 전원 차단 직전 파일이 덜 써짐 | 파일을 쓸 때마다 디스크에 확실히 기록(fsync, macOS는 F_FULLFSYNC). 비정상 종료 뒤 이어하기 때 **마지막 20개를 해시로 다시 확인**하고 이상하면 다시 꺼냄 | 테스트(내용 손상·파일 누락 흉내). **실제 전원 차단은 미확인** |
| 반쯤 쓴 파일 | `.part`로 쓰고 끝나면 이름 변경. 실패하면 지움 | 테스트 |
| 도구를 두 번 실행 | 세션 폴더 잠금으로 두 번째 실행 거부 | 테스트 |
| 브라우저 탭을 닫음/새로고침 | 작업은 서버에서 계속되고, 다시 열면 진행 중인 화면으로 돌아감 | 브라우저 |
| 도구와 화면의 연결이 끊김 | 화면에 안내를 띄우고 계속 다시 연결을 시도 | 코드 검토만. **브라우저 확인은 못 함** |
| 배터리로 실행 | 경고 배너 | 테스트(파싱). 실제 배터리 상태 화면은 미확인 |
| 맥이 잠자기에 들어감 | `caffeinate`로 방지(전원 연결 시). 덮개를 닫으면 막지 못하므로 경고 | **미확인** |
| 다시 검사해서 이전 결과와 섞일 위험 | 옛 세션 파일을 `archive_<시각>/`로 보관 | 테스트 |

## 알려진 한계
- 읽기 오류 때문에 건너뛴 파일은 자동으로 다시 시도하지 않는다(디스크 상태가 좋아진 뒤 다시 시도하는 기능은 없음).
- 전원 차단 대응은 "쓸 때 확실히 기록 + 이어할 때 다시 확인"이며, 실제 전원 차단으로 시험하지는 않았다. 저장 드라이브가 쓰기 캐시를 거짓으로 보고하면 완전히 막을 수 없다.
- 지문은 디스크 앞 64KB와 크기로 만든다. 같은 복제본 디스크는 구분하지 못한다.
- 자동 재개(사람이 누르지 않고 이어서 하기)는 일부러 넣지 않았다. 케이블이 헐거워 계속 끊기는 상황에서 반복 시도가 상태를 더 나쁘게 만들 수 있어서, 재연결을 알려 주고 사람이 누르게 했다.

## 윈도우 (2026-11-23)
- 연결 끊김 판정은 `blockdev.device_gone()` 이 맡는다. 윈도우 오류 코드(21, 55, 483, 1117, 1167)를 끊김으로 본다.
  파이썬이 윈도우 오류 코드를 채워 주지 않는 경우는 구분할 수 없고, 그때는 연속 실패 중단 규칙이 멈춘다.
- **미확인**: 실제 케이블 분리 때 어떤 오류가 나는지, UAC 창, 덮개 닫기/잠자기(`SetThreadExecutionState` 는 호출만 확인).
