# 02. UI 명세

> **현재 화면은 v2 입니다** (시안: [mockup/ui-v2.html](mockup/ui-v2.html), 구현: `apfsrecover/ui/index.html`).
> 아래 "화면 1~6"은 v1(6단계 탭) 설계이며 기록으로 남긴다.
>
> ## v2: 3단계 (디스크 → 복구 설정 → 진행·결과)
> | 화면 | 내용 |
> |---|---|
> | 디스크 | 이름·연결·형식·용량 카드. 읽기 전용 안내는 제목줄 배지와 이 화면의 안내 한 줄뿐 |
> | (검사) | 디스크를 훑는 진행 화면. 시안에는 없던 화면이며 같은 디자인(링·통계)을 쓴다. 이미 검사한 같은 디스크면 건너뛴다 |
> | 복구 설정 | 사진·RAW·영상 카드(개수·용량), 저장 폴더, `_의심` 토글, 한 문장 요약, [고급 설정: 나눠서 꺼내기·다시 검사·전체 검사] |
> | 진행 | 링, 꺼낸 파일·용량·남은 시간, 종류별 개수, 방금 꺼낸 파일 썸네일. 이어서 [열림 확인] 단계 |
> | 결과 | 개수·열림 확인 요약, 썸네일 격자, [폴더 열기], 문제 파일·검증 방법은 접어 둠, [보고서 저장] |
>
> 시안과 달라진 점(구현하며 필요해서 바꾼 것): ① 검사 진행 화면 추가 ② APFS 가 아닌 디스크도 선택 가능(경고 칩만 표시. 윈도우에서 포맷된 디스크도 서명 복구가 되기 때문)
> ③ 결과 문구 "모두 열리는 것을 확인" → "모두 정상으로 확인"(영상은 구조 확인까지만 하므로) ④ 결과에 "자세히"(검증 방법)를 항상 표시 ⑤ 고급 설정 추가 ⑥ 제목줄에 [종료] 버튼
> ⑦ 전용 창에서는 화면 위쪽의 이름을 숨김(윈도우 제목줄이 이미 보여 줌)

# (이전 설계) v1 UI 명세

시안: [mockup/index.html](mockup/index.html)

## 공통
- 상단에 항상 **"읽기 전용: 원본 디스크에는 아무것도 쓰지 않습니다"** 표시
- 진행 단계 표시줄: ① 디스크 ② 검사 ③ 결과 ④ 계획 ⑤ 복구 ⑥ 검증
- 판정 라벨은 3종류만 쓴다: `확인됨`, `의심`, `불명`. 색만으로 구분하지 않고 글자와 아이콘을 같이 쓴다
- 오래 걸리는 작업은 항상 **진행률, 처리 속도, 남은 시간 추정, 취소 버튼**을 보여 준다
- 오류 문구는 "무슨 일이 일어났나 → 데이터는 안전한가 → 다음에 할 일" 순서로 쓴다
  - 예: "하드와 연결이 끊겼습니다. 원본은 읽기만 했으므로 안전합니다. 케이블을 다시 꽂고 [다시 연결]을 누르세요."

## 화면 1. 디스크 선택
- **외장 디스크 목록**을 보여 준다(이름, 용량, 연결 방식, 식별자). 내장/시스템 디스크는 목록에 올리지 않는다
- 선택한 디스크 요약: 파티션, 파일시스템 인식 결과(예: "APFS, 마운트되지 않음")
- 버튼: `[검사 시작]`
- 상태: 디스크 없음 → "연결 후 [새로고침]". 권한 부족 → 관리자 권한으로 다시 실행하는 방법 안내

## 화면 2. 검사 진행
- 단계 표시: 구조 확인 → 데이터 분포 → 파일 찾기
- 진행률 막대, 읽은 GB / 전체 GB, MB/s, 남은 시간, 지금까지 찾은 파일 수
- `[취소]`(디스크에는 영향 없음 안내), 케이블이 빠지면 자동 중지 + `[다시 연결]`
- 예상 시간이 길면(예: 1시간 이상) 시작 전에 알려 준다

## 화면 3. 검사 결과
- **한 줄 결론**: 예) "사진·영상 N개(약 X GB)를 찾았습니다. 원래 파일명은 복구할 수 없습니다."
- 종류별 표: 개수, 용량, 구조 점검 결과(확인됨/의심)
- 촬영일 분포(월별 막대), 카메라 모델 목록
- 디스크 상태 요약: 새로 초기화된 컨테이너인지, 암호화 흔적, 데이터가 있는 구간
- 모르는 것 목록: "삭제된 옛 파일이 섞여 있을 수 있음(구분 불가)" 등 알려진 한계
- 버튼: `[복구 계획 세우기]`, `[결과 저장]`

## 화면 4. 복구 계획
- **무엇을**: 종류 체크(JPEG, RAW, 영상), 촬영일 범위, `의심` 포함 여부
- **얼마씩**: 한 묶음 크기를 "개수" 또는 "GB"로 입력. 묶음이 몇 개로 나뉘는지 즉시 계산해서 표시
- **어디에**: 저장 폴더 입력/선택 → 즉시 검사
  - 여유 공간, 이번 묶음 필요량, 마진 → `충분함 / 부족함`
  - 거부: 원본 디스크 안, 저장소 폴더 안, 시스템 폴더
- 폴더 구조 미리보기(날짜별 예시 3줄)
- 버튼: `[이 묶음 복구 시작]`(비활성 조건을 이유와 함께 표시)

## 화면 5. 복구 진행
- 묶음 번호(예: 2/7), 파일 N/M, GB, 속도, 남은 시간
- 최근 꺼낸 파일 목록(이름, 크기, 상태)
- `[일시정지]`, `[중단]`. 중단/끊김 시 이어서 할 위치를 저장하고 안내
- 묶음이 끝나면 요약 + `[다음 묶음]` `[검증으로]`. 폴더를 비워도 이어갈 수 있음을 안내

## 화면 6. 검증 결과
- 파일 수: 열림 확인 N / 실패 M / 미검사 K
- 실패 목록(이유: 잘림, 구조 오류, 헤더 불일치)과 `[실패 파일 폴더 열기]`
- 영상은 "구조 확인까지만 했고 재생 확인은 하지 못했다" 같이 **검증 범위**를 명시
- `[보고서 저장]`(텍스트, 개인정보 가림)

## 접근성·기타
- 키보드만으로 모든 버튼에 접근 가능, 상태는 글자로도 표시
- 라이트/다크 둘 다 지원
- 모바일 폭은 지원 대상이 아니지만 좁은 창에서도 깨지지 않게 한다
- 영어 번역은 문구를 한곳에 모아 두어(`i18n`) 나중에 추가한다
