# 07. 공개 준비 로드맵 (2026-11-25)

배경: 경쟁 제품(Recoverit·EaseUS·Disk Drill·R-Studio·PhotoRec)과 사용자 불만을 비교한 결과,
엔진의 안전성·정직함(읽기 전용, 확인됨/의심/불명, 꺼낸 뒤 열림 확인, 포맷 전 점검)은 이미 앞선다.
부족한 것은 **"찾은 파일을 미리 보고 골라서 꺼내는" 흐름**과 **꺼낸 파일의 정리(이름)** 다.

**포지셔닝:** 무료·용량 무제한·원본에 손대지 않음·꺼낸 뒤 열리는지까지 확인하는 사진/영상 복구.
대상은 포맷·초기화된 외장하드나 SD카드를 가진 카메라 사용자.

## P0

### A. 윈도우 실제 디스크 실측
`04-distribution.md`에서 미확인으로 남은 것을 실제로 확인한다. 시연 중 실패하면 신뢰를 잃으므로 공개 전에 반드시 한다.

확인표(결과는 `reports/NOTES.md`에 기록):
1. `RecoveryTool.exe` 더블클릭 → UAC 창 → 전용 창 열림
2. APFS 외장 디스크가 목록에 보임, 파티션 오프셋이 맞음(GPT 512/4096 섹터)
3. 기본 검사 10분 이상 실행, MB/s가 맥과 비슷한지
4. 검사 중 케이블 분리 → "연결 끊김" 화면 → 다시 꽂기 → [이어서 하기]
5. 꺼내기 → 열림 확인 → 결과까지 한 번
6. 125%·150% 배율에서 화면 깨짐 확인
7. WebView2가 없는 환경(가능하면)에서 브라우저로 열리는지

코드 변경은 실측에서 나온 문제만 고친다.

### B. 검사 중 미리보기 저장
목표: 꺼내기 전에 사진 썸네일을 보여 준다. **디스크를 따로 다시 읽지 않는다.**

- 검사(`catalog.py`)는 파일 시작 부분을 이미 메모리에 갖고 있다. 이때 **내장 미리보기**를 꺼내 세션 폴더 `thumbs/<id>.jpg`에 저장한다.
  - JPEG: EXIF IFD1의 썸네일(태그 0x0201/0x0202, 보통 160×120, 수 KB). `exif.py`의 TIFF 파서를 확장한다.
  - CR3: `uuid` 상자 안의 `THMB` 상자(160×120 JPEG).
  - 그 밖의 RAW(TIFF 계열): IFD0/IFD1의 미리보기 JPEG가 버퍼 안에 있을 때만 저장한다.
  - HEIC·PNG·영상: 저장하지 않는다(종류 아이콘으로 표시).
- 미리보기가 버퍼 밖에 있으면 건너뛴다. 검사를 느리게 만들지 않는 것이 우선이다.
- catalog 줄에 `"thumb": true`를 추가한다(`compat.py` 기본값 false). 기록 형식 번호를 3으로 올린다.
- 이전 버전 세션은 미리보기가 없다. 화면은 "다시 검사하면 미리보기가 생겨요"라고 안내한다(재사용 검사는 건너뛴 구간의 썸네일을 만들지 못한다. 알려진 한계로 적는다).
- 용량: 사진 10만 장 × 약 8KB ≈ 800MB. 세션 폴더에 저장하므로 저장 공간 검사에 포함한다.
- 테스트: 합성 JPEG(IFD1 썸네일 있음/없음/잘림), 합성 CR3, 버퍼 경계에 걸친 경우.

**큰 미리보기(선택 사항):** 하나를 눌러 크게 볼 때만 원본 장치에서 그 파일을 읽어 Pillow로 줄인다(`/api/preview?id=`).
작업(검사·꺼내기)이 진행 중이면 HDD 탐색이 섞여 속도가 떨어지므로 **작업 중에는 막고** 내장 썸네일만 보여 준다.
`lock.py`로 장치 사용 중 여부를 확인하고, 읽기 범위는 catalog의 offset/length로 제한한다.

### C. 결과 탐색 화면 (꺼내기 전)
목표: 사용자가 "내 사진이 있다"를 확인하고 원하는 것만 고른다.

**서버 API (새로)**
| 경로 | 내용 |
|---|---|
| `GET /api/catalog/items?kind=&from=&to=&model=&status=&sort=&cursor=&limit=` | 필터한 목록을 쪽 단위로(기본 200개). 응답: `{items:[{id,kind,length,taken,model,structure,thumb}], next, total, bytes}` |
| `GET /api/catalog/facets` | 종류별·월별·카메라별·판정별 개수와 용량(필터 칩과 타임라인용) |
| `GET /api/catalog/thumb?id=` | `thumbs/<id>.jpg`. 없으면 404 |
| `GET /api/preview?id=` | 큰 미리보기(B의 선택 사항) |

- catalog가 수십만 줄일 수 있다. 서버는 세션을 고를 때 한 번 읽어 메모리에 둔다(줄당 약 200B → 50만 줄 100MB 미만). 파일이 바뀌면(mtime) 다시 읽는다.

**선택 저장 방식 (plan.json)**
수십만 개의 id를 그대로 저장하지 않는다. **필터 + 예외**로 저장한다.
```json
{"kinds": [...], "date_from": "...", "date_to": "...", "models": ["Canon EOS R8"],
 "include_suspect": true, "exclude_ids": [12, 98], "include_ids": []}
```
- `extract.select()`에 `models`, `exclude_ids`, `include_ids`를 추가한다. 없으면 지금과 같이 동작한다(이전 plan 호환).
- 테스트: 필터만 / 예외만 / 둘 다 / 이전 plan.json.

**화면**
```
┌ 필터: [사진 1,204][RAW 880][영상 32]  기간 [2024-01 ~ 2024-12]  카메라 [모두 ▾]  [확인됨만] ┐
│ 월별 막대 (누르면 그 달로 필터)                                                            │
├────────────────────────────────────────────────────────────┬───────────────────────────────┤
│ ☑ 2024-03-06 (128)                                         │  미리보기                      │
│ [■][■][■][■][■][■][■][■]  ← 날짜별로 묶은 격자, 체크박스 │  2024-03-06 14:30:12           │
│ ☐ 2024-03-07 (54)                                          │  Canon EOS R8 · 6.1MB · 확인됨 │
│ [■][■][■]...                                               │                                │
├────────────────────────────────────────────────────────────┴───────────────────────────────┤
│ 1,180개 · 7.2GB 선택                                    [저장 폴더 ▸ D:\복구]  [꺼내기]   │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```
- 격자는 가상 스크롤로 만든다(보이는 칸만 그림). 칸 크기는 고정(`02-ui-spec` 흔들림 방지 규칙).
- 썸네일이 없는 항목은 종류 아이콘 + 크기를 보여 준다. 판정은 칩(확인됨/의심)으로 표시하고 색만으로 구분하지 않는다.
- 날짜 머리의 체크박스로 그날 전체를 선택·해제한다. Shift+클릭으로 범위를 고른다.
- 기존 "무엇을 꺼낼까요?" 화면의 저장 폴더·묶음·의심 토글은 오른쪽 아래 [꺼내기] 전 확인 창으로 옮긴다.
- 기존 종류 카드 화면은 없애지 않고 [간단히 보기]로 남긴다(사진만 수만 장일 때 빠른 길).
- 시안을 먼저 만든다: `design/mockup/ui-v6-browse.html`(서버 없이 가짜 데이터로).

### D. 촬영 시각으로 파일 이름 — **구현됨 (2026-11-25)**
PhotoRec 사용자의 가장 큰 불만(이름 없는 파일 수천 개)을 해결한다.

- 새 이름: `사진/2024-03-06/20240306_143012_CanonEOSR8_000123.jpg` (`extract.file_name`)
  - 시각 없음: `jpg_000123_blk25792.jpg`(이전과 같음)
  - 카메라 이름은 영문·숫자만 남기고 16자로 자른다. 없으면 생략한다.
  - 끝의 id가 있어 같은 초에 찍은 사진도 이름이 겹치지 않는다.
- 꺼낸 파일의 수정 시각을 촬영 시각으로 맞춘다(`os.utime`). 탐색기·사진 앱에서 날짜순 정렬이 촬영 순서와 맞는다. 실패해도 파일은 그대로 둔다.
- `plan.json`의 `layout`으로 구분한다(`extract.resolve_layout`): 계획에 적힌 값 → 이미 꺼낸 파일이 있으면 그때 방식 유지(`layout` 이 없는 옛 기록은 이전 방식) → 처음이면 `kind/date/taken`. 이어하는 중에는 이름 규칙이 바뀌지 않는다.
- 영상(UTC 시각)은 폴더 날짜와 같은 방식으로 이 컴퓨터의 현지 시각으로 바꿔 이름에 쓴다(폴더와 이름의 날짜가 일치). 시간대가 다른 곳에서 찍은 영상은 몇 시간 어긋날 수 있다(이전부터 있던 한계).
- 테스트: `tests/test_extract.py`의 `NamingTest` 5개(이름 규칙, 영상 현지 시각, 새 세션 이름·수정 시각, 이어하기 중 유지, 옛 기록 유지). 전체 147개 통과.
- 남은 것: 설정에서 이전 방식을 고르는 화면(결정 2), 결과 화면 문구("원래 파일명은 복구할 수 없습니다")에 "촬영 시각으로 이름을 지었어요" 추가.

### E. 검사 탭 단순화 · 아이콘 통일
- 검사 탭: [기본 검사] 카드 하나를 크게 둔다. 끝부분 촘촘 검사·파티션 찾기·전체 검사는 **"고급 검사"** 접힘 안으로 옮긴다.
  - 기본 검사가 끝나면 결과 화면에서 "더 찾고 싶으면 고급 검사"로 안내한다.
- 이모지(📁 ⟳ 등)를 SVG `symbol` 선 아이콘으로 모두 바꾼다.
- 용어 보조: 화면 문구는 그대로 두고, 도움말에 "꺼내기 = 복구, 열림 확인 = 복구 후 검증" 같은 대응표를 넣는다(영어판·검색 대비).

- `/api/job` 응답에 `recent_thumbs: [id…]`(최근 12개)를 넣는다. B가 있으면 화면만 바꾸면 된다.

### G. 영상 재생 확인 · 첫 프레임
- ffprobe·ffmpeg를 함께 배포한다. LGPL 빌드를 쓰고 라이선스 문구를 포함한다. exe 용량이 커지므로(수십 MB) 별도 내려받기도 검토한다.
- 열림 확인: 지금 하는 ffprobe 길이 읽기에 더해, 마지막 몇 초를 실제로 디코드해 끝까지 재생되는지 본다(`-ss` + `-frames`).
- 결과 화면 썸네일: 영상 첫 프레임.
- 결과 문구를 "구조 확인"에서 "재생 확인"으로 올린다(검증 범위를 사실대로).

### H. 영어 화면
- `index.html`의 문구를 `ui/i18n/ko.json`으로 옮기고 `en.json`을 만든다. 서버 오류 문구도 코드 + 문장으로 분리한다.
- 언어는 OS 언어를 따르고 설정에서 바꿀 수 있다.
- 문구가 길어져 레이아웃이 흔들리지 않는지 영어로 다시 측정한다.

### I. 조각난 영상 복구 (먼저 조사)
- 조사 질문: 실제 디스크의 `_의심` 영상 중 몇 개가 "조각남"이고 몇 개가 "끝 잘림"인가?
  끝 잘림이면 `moov`가 없는 경우가 많다. 같은 카메라의 정상 영상 `moov`를 본으로 다시 만드는 방식(untrunc 계열)을 쓸 수 있다.
- 조사 결과가 나오면 구현 여부를 정한다. 조사는 1회 분량이다.

## 결정이 필요한 것
1. **코드 서명:** SmartScreen 경고를 없애려면 유료 인증서가 필요하다(연 단위 비용). 무료로 공개하는 동안은 경고 + 안내 문구로 갈지 정한다.
2. **새 이름 규칙(D)을 기본값으로 할지:** 권장은 기본값. 설정에서 이전 방식을 고를 수 있게 한다.
3. **P2-J를 할지:** 제품 범위의 문제라 P0이 끝난 뒤 정한다.
4. **ffmpeg 배포 방식(G):** exe에 포함 / 첫 사용 때 내려받기.
